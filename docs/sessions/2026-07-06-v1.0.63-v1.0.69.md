## Summary

Seven versions released fixing three user-reported issues:
1. BIOS report silently failing (v1.0.59 regression)
2. "Sem localidade" ghost group reappearing
3. Deleted machines coming back after agent re-registration

## v1.0.63–v1.0.66 — BIOS Report Fix + Visual Feedback

### Root Cause
The `will-download` handler added in v1.0.59 (for Módulo Relatório) intercepts ALL session downloads in Electron. The BIOS report used the old blob: URL pattern (`URL.createObjectURL()`). For blob: URLs, `item.getFilename()` returns `''` → `setSavePath(downloadsDir + '')` receives only the directory → Electron creates a **folder** instead of a file → download silently "completes" with no file written.

### Fix (v1.0.63)
Replace blob: URL pattern with `window.electronAPI.downloadFile(directHttpUrl)`:
- Triggers `win.webContents.downloadURL(url)` with a real HTTP URL
- `will-download` fires with real URL → `item.getFilename()` reads `Content-Disposition` header → correct filename

### Visual Feedback (v1.0.66)
Added `biosState` state machine (`null | 'loading' | 'done' | 'error'`) with:
- Button shows `⏳ Gerando…` (disabled) while download in progress
- `onDownloadDone` filtered by `filename.startsWith('relatorio-bios-')` to avoid collision with Módulo Relatório
- 30-second safety timeout if `download-done` event never arrives
- Button shows `✅ Salvo!` / `✕ Erro`, resets after 4s

**Files changed**: `dashboard/src/App.jsx`

## v1.0.64–v1.0.65 — Permanent Machine Deletion

### Root Cause
"Remover do grupo" in MachineCard context menu called `onMoveToGroup(id, '')` → `location: ''` → server stored empty location → group with empty name appeared as "Sem localidade".

### Decision
Replace "Remover do grupo" with "✕ Excluir máquina" — permanently delete from system.

### Implementation

**`server/db.js`** — `deleteMachine(id)`:
```javascript
db.prepare('DELETE FROM metrics  WHERE machine_id=?').run(id)
db.prepare('DELETE FROM commands WHERE machine_id=?').run(id)
db.prepare('DELETE FROM events   WHERE machine_id=?').run(id)
db.prepare('DELETE FROM machines WHERE id=?').run(id)
// Note: win_events, insights, nfce_index, dr_backups have ON DELETE CASCADE
```

**`server/routes/machines.js`** — `DELETE /:id` endpoint

**`dashboard/src/api.js`** — `deleteMachine(id)`

**`dashboard/src/hooks/useMachines.js`** — `deleteMachine` callback

**`dashboard/src/components/MachineCard.jsx`** — context menu item with `window.confirm()`

**`dashboard/src/components/LocationGroup.jsx` + `SplitView.jsx`** — `onDeleteMachine` prop

## v1.0.67 — Machine Deletion Blocklist

### Root Cause (bounce-back cycle)
1. Admin deletes machine → row removed from DB (token gone)
2. Go agent still running → sends heartbeat every ~30s
3. Server returns 401 (token not found)
4. Agent calls `POST /api/register` with same `machineId`
5. `registerMachine()` finds no existing row → `INSERT INTO machines ... location='Temporário'`
6. `broadcast('machine:update')` → dashboard re-fetches → machine reappears

### Fix

**New SQLite table** (added to incremental migrations):
```sql
CREATE TABLE IF NOT EXISTS deleted_machines (
  id         TEXT PRIMARY KEY,
  deleted_at TEXT NOT NULL
)
```

**`db.deleteMachine(id)`** — inserts into blocklist:
```javascript
db.prepare('INSERT OR REPLACE INTO deleted_machines (id, deleted_at) VALUES (?, ?)').run(id, now)
```

**`db.isDeletedMachine(id)`** — checks 10-minute TTL:
```javascript
function isDeletedMachine(id) {
  const row = getDb().prepare('SELECT deleted_at FROM deleted_machines WHERE id = ?').get(id)
  if (!row) return false
  return (Date.now() - new Date(row.deleted_at).getTime()) < 10 * 60 * 1000
}
```

**`server/routes/agent.js`** — `POST /api/register` check:
```javascript
if (db.isDeletedMachine(machineId)) {
  return res.status(403).json({ error: 'Maquina removida do sistema pelo administrador' })
}
```

### TTL Design Decision
- 10 minutes blocks ~10-20 automatic re-registration attempts (every 30-60s)
- After 10 minutes, deliberate agent reinstall on same machine works normally
- Permanent blocklist would prevent legitimate reinstalls → rejected

**Files changed**: `server/db.js`, `server/routes/agent.js`

## v1.0.68 — BIOS Report Shows Save Location

The `will-download` handler already sent `savePath` in the `download-done` IPC event. Used it to:

### New IPC `shell:showItemInFolder` (`electron/main.js`)
```javascript
ipcMain.handle('shell:showItemInFolder', (_, filePath) => {
  if (typeof filePath !== 'string') return
  const resolved = path.resolve(filePath)
  const downloadsRoot = path.resolve(app.getPath('downloads'))
  // Security: only allow paths inside Downloads
  const norm = resolved.toLowerCase()
  const prefix = downloadsRoot.toLowerCase() + path.sep
  if (norm !== downloadsRoot.toLowerCase() && !norm.startsWith(prefix)) return
  shell.showItemInFolder(resolved)
})
```

### `preload.js`
```javascript
showInFolder: (p) => ipcRenderer.invoke('shell:showItemInFolder', p)
```

### `App.jsx` changes
- Added `biosSavePath` state
- `onDownloadDone` callback captures `savePath`
- Timeout increased to 8s
- Button in `done` state: `✅ Salvo — 📂 Mostrar` (clickable → opens Explorer)
- Clicking `done` button calls `showInFolder(biosSavePath)` instead of starting new download
- Tooltip shows full path when in `done` state

**Files changed**: `electron/main.js`, `electron/preload.js`, `dashboard/src/App.jsx`

## v1.0.69 — Browser Fallback Fix

Without Electron API, `setBiosState(null)` was called immediately after download start → user saw no confirmation.

**Fix**: `setBiosState('done')` for 5s in `else` branch (browser path). No `showInFolder` (browser handles downloads its own way).

## Technical Gotchas Discovered

### VM file structure
Files are directly in `/opt/dt-manager/` — NOT in `/opt/dt-manager/server/`:
```
/opt/dt-manager/db.js           ← NOT server/db.js
/opt/dt-manager/routes/agent.js ← NOT server/routes/agent.js
```
Confirmed with `find /opt/dt-manager -name 'db.js'` → `/opt/dt-manager/db.js`.

### `will-download` + blob: URL = silent failure
`item.getFilename()` returns `''` for blob: URLs → `setSavePath` receives only the directory → Electron creates a folder. Always use real HTTP URLs with `webContents.downloadURL()` for programmatic downloads when `will-download` handler is active.

### GitHub release assets — spaces become dots
`gh release create` sanitizes filename spaces to dots in asset URLs.
`Delirio Manager Setup 1.0.69.exe` → download URL: `Delirio.Manager.Setup.1.0.69.exe`
Must download with dotted URL but save with spaces to match `latest.yml`.

### `az vm run-command --scripts` as PowerShell array
Each string in the array runs independently — failure in one does not stop others (no `&&` chaining). PM2 can start even if prior `curl` commands failed. Always verify full stdout output.
